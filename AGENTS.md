# AGENTS.md

Guide for AI agents (and humans) working on Pencil.js. Read it before changing anything.

Pencil.js is a modular, object-oriented 2D drawing library on top of the Canvas 2D API.
Core values: **OOP, modularity, documentation, performance and size**. Every change is judged against them.

## Stack

- TypeScript 6 (strict), ESM only, single package `pencil.js` (one module per class, importable as `pencil.js/<module>`).
- Vite 8 (rolldown) for the build, the playground and the benchmark.
- Vitest 5 with jsdom + `@napi-rs/canvas` (real canvas rendering in tests), `pool: "vmThreads"`.
- ESLint 10 flat config (typescript-eslint + @stylistic).
- Docs: VitePress + TypeDoc (`docs/`), deployed by Vercel (project `docs`).
- Runtime dependencies: `colord` (colors), `text-direction`, `zeptomatch` (sprite selectors). Keep this list short.
- Node.js ≥ 22.12 for tooling.

## Commands

| Command | What it does |
| --- | --- |
| `npm run dev` | Playground (`playground/`) with the local sources |
| `npm test` | Unit, behavior and visual tests |
| `npm run coverage` | Tests with coverage |
| `npm run test:visual:update` | Regenerate visual references (check every changed image before committing) |
| `npm run lint` / `npm run typecheck` | ESLint / `tsc --noEmit` |
| `npm run build` | Modules (`dist/*.js`), CDN bundles (`pencil.esm.js`, `pencil.min.js`) and declarations |
| `npm run size` | Gzipped size report (run `build` first) |
| `npm run bench` / `npm run bench:headless` | Browser benchmark against published versions / headless Playwright benchmark |
| `npm run docs:dev` / `npm run docs:build` | Docs with the generated API reference |

Before pushing: `npm run lint && npm run typecheck && npm test && npm run build && npm run size`. CI runs the same on Node 22 and 24.

## Layout

```
src/                One TS module per class (+ its colocated *.test.ts)
src/internal/       Private helpers (canvas, render state, gradients) — not part of the public API
src/index.ts        Named exports, default `Pencil` namespace, `from()`, `register()`, `use()`
test/               Shared helpers (_pointer, _path-recorder …), setup, cross-module and regression tests
test/visual/        Visual scenes, references (PNG) and their runner
test/fonts/         Subsetted DejaVu fonts used by the tests
docs/guide/         Hand-written guides (getting started, concepts, migration …)
docs/modules/       One page per module
docs/api/           Generated by TypeDoc (gitignored)
benchmark/          Browser and headless benchmarks
playground/         Manual testing page
```

## Conventions

### Code style

- 4 spaces, double quotes, semicolons, trailing commas on multi-line, Stroustrup braces, space before function parentheses (ESLint enforces it).
- Relative imports use the **`.js` extension** (`import Position from "./position.js"`): TypeScript and Vite resolve it to the `.ts` file, and the emitted `dist/` works as is.
- Type-only imports use `import type` (`verbatimModuleSyntax`).
- Every public member has a TSDoc comment (it feeds the API reference).

### Classes

Each class module follows the same shape:

- `export class Foo` **and** `export default Foo`, also added to `src/index.ts` (named export, `Pencil` namespace and `register()` list when serializable).
- `static get className ()` returns the class name (serialization must survive minification).
- `static get defaultOptions ()` spreads `super.defaultOptions`; options are always read from `this.options`.
- `static get events ()` is built once (module-level cache) and spreads `super.events`.
- `toJSON()` returns plain data and `static from(definition)` revives it; add a test for the round trip.
- Keep v3 public names and signatures. A behavior change must be a real fix and be listed in `docs/guide/migration.md`.

### Custom shapes

- Override `trace(path)` to describe the shape. Override `pathDependencies` (in the same class as `trace`) to keep the path between renders while those values don't change.
- Override `makePath` only for non-path drawing (text, images). Never override `render` to customize drawing: parents call the internal `renderTree`.

### Tests

- Unit tests are colocated: `src/foo.ts` → `src/foo.test.ts`. Regressions found in reviews go in `test/regressions.test.ts`.
- Visual tests: add a small, targeted scene in `test/visual/scenes.ts`, generate its reference with `npm run test:visual:update`, then **look at the PNG**. Tolerance is near zero on purpose — don't raise it to make a test pass.
- In tests, `sans-serif` and `serif` are mapped to the bundled fonts; image urls like `name-20x10.png` load a fake 20×10 image, and urls containing `error` (or without an image extension) fail.
- Pointer interactions: use `test/_pointer.ts` (`pointer`, `drag`).

### Git

- Commit messages use **[gitmoji](https://gitmoji.dev/)** followed by a short English summary: `🐛 Fix …`, `✨ Add …`, `⚡ …`, `♻️ …`, `✅ …`, `📝 …`, `🔧 …`, `👷 …`. Details go in the body as a list.
- v4 work happens on the `v4` branch.

## Pitfalls

### Rendering pipeline

- `Container.renderTree` sets the **absolute transform** of each element (no `save`/`restore` per element). Never leave the context transformed: undo your own `translate`, or `save`/`restore` around it.
- `src/internal/render-state.ts` remembers context properties during a render pass to skip redundant sets. Set styles through `set()` / `setStyle()`, never directly. Any drawing that changes the context outside of them must make `hasPureDrawing` return false (the render pass then calls `invalidate()`).
- `draw` events are only created when someone listens (`hasListener`). Targeted listeners of ancestors are ignored on purpose (perf).
- Plain rectangles with no rotation or scale and plain colors are drawn with `fillRect`/`strokeRect` in their parent space (`canDrawInParentSpace` / `drawInParentSpace`). Gradients and patterns can't use this path: they are positioned relative to the component.
- Hit-testing (`getTarget`, `isHover`) uses relative transforms with `save`/`restore`: keep it consistent with `renderTree` (position → clip → rotation → scale).

### Performance and memory

- The render loop must not allocate: no `Position.clone()`, array spreads, closures or `new DOMMatrix()` per element per frame. Reuse module-level or instance buffers.
- Cache what is costly and invalidate on change (text measures, tinted images, path cache via `pathDependencies`).
- Check `npm run size` and `npm run bench:headless` on rendering changes; 16 000 squares should stay close to raw canvas.

### TypeScript and classes

- `useDefineForClassFields` is **false**: declared fields don't reset what a parent constructor already set. Keep it.
- Private `#fields` with an initializer are set **after** `super()`. A parent constructor calling an overridden method (like `setOptions` or a setter) that reads a subclass `#field` would crash: give such fields a default or guard them.
- `Position.from` returns the same instance when given a `Position`; copy it (`clone()`) before storing if the caller may mutate it.

### Dependencies

- Don't re-implement what a small, well-maintained package already does, but don't add a dependency for a few lines either. Prefer light, tree-shakable packages and check the size impact.

### Docs and deployment

- `docs/api/` is generated: edit the TSDoc comments, not the Markdown.
- Vercel builds the docs with `npm run docs:build`. `.vercelignore` must keep `docs/`, `src/`, `media/` and the configs; `vercel.json` enables `cleanUrls` (VitePress links have no `.html`).
